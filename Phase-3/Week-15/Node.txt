 # 1.2 What is back-end Development 

    Back-end (server-side) development is the logic that `Receive requests` from clients.   gets the right data from the database and sends it back  

## The four pillars of back-end development
    Server 
        Recrive requests, send responses include serving a static website.
    Back-end logic
        Authentication (Who are you?) and authorization (what are you allowed to do?), plus your business logic and rules.
    DataBase 
        Store and retrieve data and interact with with it efficiently.
    APIs
        Allow communication between the frontend and backend, and define how different software components interact. 

## What is Our Job as a Back-end Developer
    Server-side logic
        Build the script that decides what happens.
    DataBase query
        Write queries to store and retrieve data.
    Communication
        Organize and manage browser <-> server traffic over TCP/IP.
        


# 1.3 Modular structure & namespace collision 
    Modular design is GENERAL DESIGN PRINCIPLE 
        not special to Node or even to programming.

# Why does Node need it? Global namespace collision
    NameSpace
        The place/space where the name of a variable function is accessible
    Name Collision
        The accidental overriding of a variable/function because the same name was used in different places.

    Eg:-
    Developer A
        function x (){
            console.log(Developer A)
        }
        x();
     Developer B
        function x (){
            console.log(Developer B)
        }

    x();

    => now we are run in node server
        node fileName.js
            then display
                 Developer B
                 Developer B

    Because two function is Global name space





# 1.4 The IIFE way
    Immediately Invoked Function Expression
        is a function defined as an expression and `Executed Immediately` after creation. 

        (function(){
            ...Your code
        })();


    => The Shape to memorize: ()(); 
        () => first pair hold the function
        () => second pair run its right now.
     
The drawbacks of IIFE
    Wrap everything
        you must remember to Wrap  `every single file` by hand. Forget ince and the collision is back.
    Script Order matters 
        You must pay attention to the `order of your <script> tags` because file may depend o rach other's output.
            An IIFE runs Immediately possibly before a file listed above it has done its job.
This tow drawbacks are exactly why modules were invented



# CommonJS (old style)
    - crateed in 2009 because JavaScript had no standard for modularity and Nodo needed one.
    - Node's default
        uses `require()` and `module.exports`.

#ES6 modules (new style, 2015)
    - JavaScript own official standard.
    - Used by default in React, Angular and other frameworks. 
        - Uses 
            `import` => import code 
            `exports` => exports code
        - we need to configration 



    # Main Different

    | CommonJS                                      | ES6 Modules                                
| --------------------------------------------- | ----------------------------------------------- |

| `require()`                                   | `import`                                        |

| `module.exports`                              | `export`                                        |

| Older Node.js module system                   | Modern JavaScript module system                 |

| Common in older Node.js projects              | Common in modern JS projects                    |

| Imports are typically evaluated at runtime    | Imports are statically analyzable               |

| Uses `.js` normally in CommonJS Node projects | Often uses `.js`, with module configuration     |

| Common with older Node.js packages            | Used by modern browser and Node.js applications |

# The Three types of Node Modules

    1, Local module
        your own files 
            the modules you crate in your applications.
            ex :- script.js
            commonjs => script.cjs
            ES6 => script.mjs  
                        m => is module
        any .js extention file is module

    2, Core Modules
        Built into Node 
            no install needed
                they arrive when you install Node.
        Thes come free with Node 
            `fs`, `path`, `http`, `https`, `url`, `os`, `crypto`, `event`
    Eg:- in os 
        const os =require("os");

            console.log(os.arch());
            console.log(os.platform());

        then run node fileName.js

        display
            x64
            win32

        check Node.js Documentation
            https://nodejs.org/docs/latest/api/os.html
