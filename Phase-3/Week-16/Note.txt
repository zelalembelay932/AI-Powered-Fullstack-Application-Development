1.1 Database & Database Management System
    Database
        An Organqized collection of structured information, stored electronically, designed to be efficiently managed, retrieved, and updated.
    DBMS 
        The software that makes a Database useble  it facilitates easy, efficient, reliable data processing.
        Database are controlled by a DBMS

    Jobs of DBMS
        Creation, Storage, Retrival, Updating, Redundancy controlled, Memory, Access control.


1.2 Relational VS Non-relational Database
    Relational(SQL)
        structured around  `Multiple table that interrelted` like an Organqized set of spreadsheed. 
        Each table holds one type of data. 
            Eg:-
                MySQL
    Non-relational(NoSQL)
        No fixed table structure, Oprates around `objects or documents often key-value pairs resembling JSON. 
            Eg:-
                MongoDB

    Same data, to shapes

    SQL a `user table`
    id   name       email
    1    Abebe      abebe@gmail.com
    2    Kebede     kebede@gmail.com

    # Every row has the same  columns.
    the shape is fixeed in advance


    NoSQL a `user` collection
    [
        {"name": "Abebe", "email": "abebe@gmail.com"},
        {"name": "kebede", "email": "kebede@gmail.com", "phone": "0912345678"}
    ]
    Each documents can have different fileds. "Kebede has a phone number, Abebe doesn't. Nobody complains.




    Primary key & Foreign keys

    Primary key
        A `Unique identifier` with in a table, no two rows can share one and it can't be empty.
            it's how a row is found and referenced.

    Foreign key
        a column in one table that references the primary key of another this is literally how table relate to each other.

1.3 HTTP verbds and their database function

    Think of a library

    GET => Retriving data
        Browse the library to find and read something.
            without changing anything
    POST => Creating new data 
        Add a brand-new book the collection
    PUT => Complete replaceement
        Swap the entire book for a new edition.
        The client send the whole updated representayion.
    PATCH => Partial update
        Add one chapter, or fix one section `without rewriting the rest. 
        The client send only what changed.
    DELETE => Removing data
        Take the book `permanently off the shelf`.
